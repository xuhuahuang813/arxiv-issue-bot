### 1. Efficient Semantic ORDER BY via Transitivity-Aware LLM Batch Sorting

- arXiv ID: `2611.32073v1`
- Authors: Akinkunle Akintayo Akinola, Arijit Khan
- Published: 2026-11-24
- Categories: `cs.DB`
- Links: [abs](http://arxiv.org/abs/2611.32073v1) | [pdf](https://arxiv.org/pdf/2611.32073v1)

Large language models (LLMs) enable declarative semantic sorting through LLM-ORDER BY operators that rank tuples according to natural-language criteria over unstructured data. Executing such operators efficiently is challenging because LLM comparisons are expensive, stochastic, and sometimes inconsistent. Pairwise approaches require many costly calls. Listwise approaches such as external merge sort rank several items per call, but they follow a fixed merge schedule and keep no record of earlier answers: each merge call re-asks orderings that previous calls have already revealed, directly or by transitivity. We present Transitive Batched Sort (TBS), a transitivity-aware physical operator for semantic sorting that records every revealed preference in a global acyclic preference graph and issues a listwise request only for items whose relative order is not yet implied. To scale, TBS stores only directly observed preferences and answers transitivity queries through a memory-efficient reachability index; to handle noisy LLM outputs, it validates responses and rejects cycle-inducing updates. We evaluate TBS on six benchmarks spanning structured sorting, product price ranking, passage ranking, and personalized recommendation with four LLMs. TBS reduces API calls by 12-20x relative to pairwise quicksort and, at the same batch size, uses 1.1-1.6x fewer calls and 1.3-5.3x lower cost than listwise merge sort while achieving competitive or higher ranking quality across most benchmarks; on Amazon it scales to one million products. These results show that reusing previously inferred preference relations, rather than re-querying them, is an effective foundation for scalable semantic ORDER BY operators.

### 2. Toward Database-Native Genomics: A Vision for Declarative Genomic Analysis

- arXiv ID: `2611.31893v1`
- Authors: Dhruv Aron, Danial Saleem, James Christopher Sorenson, Xiangyao Yu
- Published: 2026-11-24
- Categories: `cs.DB`
- Links: [abs](http://arxiv.org/abs/2611.31893v1) | [pdf](https://arxiv.org/pdf/2611.31893v1)

In recent years, numerous advancements in relational database management systems (RDBMS), including cloud-native and GPU-native paradigms, have resulted in highly competitive RDBMS performance for analytical workloads. At the same time, the field of genomics has evolved into a data-intensive domain owing to the advent of next-generation sequencing; however, current genomic analysis workflows are often file-based, fragmented, and reliant on disparate tools, limiting their expressiveness, usability, performance, and scalability. This work argues for an incremental adoption of RDBMS and declarative SQL querying in genomic analysis, particularly tertiary analysis. By translating common tasks from widely-used tools like SAMtools and BEDtools into SQL queries executed in DuckDB, we demonstrate that off-the-shelf RDBMS can match or exceed the performance of existing tools while offering significant improvements in expressiveness and usability. We identify current limitations and propose practical paths forward, aiming to position relational databases as a foundational platform for modern bioinformatics workflows.

### 3. LimoBench: How Street Smart Are Large Language Models?

- arXiv ID: `2611.31682v1`
- Authors: Gautam Choudhary, Jack Peng, Udesh Kumarasinghe, Rachel Rafik, Yousef Hammad, Ahmed Samy, Walid G. Aref
- Published: 2026-11-23
- Categories: `cs.AI`, `cs.CL`, `cs.DB`
- Links: [abs](http://arxiv.org/abs/2611.31682v1) | [pdf](https://arxiv.org/pdf/2611.31682v1)

Large language models (LLMs) have transformed how humans interact with information, enabling natural-language interfaces across various domains. They are increasingly deployed for geospatial applications including map-based question answering, location-based services, and natural-language interfaces to spatial databases. But are LLMs truly location-aware, able to reliably interpret and precisely answer location queries involving real-world coordinates, points of interest (POIs), and geospatial distances? To answer this concretely, we present LimoBench, a street-level benchmark of 82 natural-language location queries over seven canonical spatial operations: geocoding, reverse geocoding, routing, directionality, range search, $k$-nearest-neighbor search, and spatial join. The queries are grounded in real map data of West Lafayette, Indiana, and are graded by location and semantic complexity. They are designed to probe LLMs' street-level spatial awareness, from simple lookups to multi-step spatial reasoning. We also present Limo, an approach based on the Model Context Protocol (MCP) that enhances the location awareness of LLMs. Limo grounds LLMs in PostGIS-backed spatial data through a compact set of tools. We find that ungrounded models mostly achieve single-digit accuracy (3.1% for GPT-6 Luna) across different spatial operations. In contrast, the same models achieve near-perfect accuracy (99.3% for GPT-6 Luna) when given access to Limo's spatial tools through MCP. Current LLMs thus have limited and unreliable street-level spatial knowledge, while grounding provides accurate answers at modest overhead (+0.2 s latency, 7.7$\times$ tokens, and 2.2$\times$ cost for GPT-6 Luna). We release the benchmark, Limo toolset, and evaluation code to encourage the community to evaluate their own location-aware LLM approaches.

### 4. Rethinking Document Indexing for LLM-based Analysis

- arXiv ID: `2611.31679v1`
- Authors: Donna Pham, Zhongwei Xu, Siyuan Dong, Haotian Gong, Lin Ma
- Published: 2026-11-23
- Categories: `cs.DB`
- Links: [abs](http://arxiv.org/abs/2611.31679v1) | [pdf](https://arxiv.org/pdf/2611.31679v1)

Documents such as clinical records, legal contracts, and scientific papers are increasingly analyzed with large language models (LLMs). The naïve approach of prompting the model with the full text for every question is slow, expensive, prone to hallucination on long inputs, and reuses no work across questions. Retrieval-augmented generation (RAG) systems build reusable state to address this, but they store it as embedded chunks: slicing text into fragments can lose the meaning that spans them, and the resulting index is tied to one embedding model, so it must be rebuilt whenever that model changes. Answering many questions over a large body of data without a full rescan, however, is not a new problem: it is the problem database indexes have been solving for decades, and we argue that this accumulated index design knowledge is waiting to be revisited for LLM access.
  As a concrete starting point, we propose Periplus, a hierarchical plain-text index inspired by the classic B+ tree. It arranges a document into pages running from general summaries at the root to specific ones at the leaves, so that each level guides the search into the next. But it departs from the B+ tree in three ways suited to LLM access: content lives at every level, the pages are plain text rather than attribute values, and navigation follows the relevance of a page summary to the question rather than a key comparison. The structure itself is discovered per document by the LLM rather than hand-designed in advance. In a preliminary evaluation on narrative and contract corpora, Periplus comes within 0.1--0.9 percentage points of the strongest baseline's accuracy while consuming 70--72\% fewer total tokens. These early results are encouraging, and they offer only a glimpse of what index design can bring to LLM-based analysis.

### 5. Agent Recovery Gone Wrong: Measuring Harm Beyond Duplicate Calls

- arXiv ID: `2611.31554v1`
- Authors: Artem Trofimov, Boris Novikov
- Published: 2026-11-23
- Categories: `cs.AI`, `cs.DB`, `cs.SE`
- Links: [abs](http://arxiv.org/abs/2611.31554v1) | [pdf](https://arxiv.org/pdf/2611.31554v1)

Code-executing LLM agents submit blocks of code that issue several API writes. If a block fails after some of its writes have taken effect, the agent rewrites the block and continues. It is unknown how often such a recovery harms the external state when the failure occurs naturally in the code written by the agent. In this paper, we measure it on recorded trajectories of AppWorld agents. In a stratified random sample of 200 candidate episodes across ten models, 145 are partial executions confirmed by the database state. In the sample, 30 of 143 confirmed partial executions with a determinable outcome are followed by a harmful recovery, and its violation remains at the end of the run, which gives a stratification-weighted estimate of 24.6%. Two thirds of the harmful recoveries duplicate an effect, and the rest delete user data or make a wrong first-time write, e.g., an order of a wrong product. A rule that searches for repeated calls finds 75% of duplications but only 41% of all harm. We also examine two sources of operation identity for an idempotency contract. In a small pilot (17 episodes, one local model), identifiers supplied by the model do not detectably reduce harm, because the model issues a new identifier for the same operation. Identity derived from the call content, evaluated counterfactually on the sample, would have matched every harmful write in 14 to 18 of the 30 harmful recoveries, but in none of those with a wrong first-time write, and it would also have matched writes required by the task in 30 episodes. Based on these results, we outline design requirements for safer agent recovery.

### 6. Energy as a Service-Level Objective: Transaction-Level Energy Attribution

- arXiv ID: `2611.32731v1`
- Authors: Julian Legler
- Published: 2026-11-24
- Categories: `cs.SE`, `cs.DC`
- Links: [abs](http://arxiv.org/abs/2611.32731v1) | [pdf](https://arxiv.org/pdf/2611.32731v1)

Service engineers assess every change against functional requirements and qualities such as reliability, performance and availability. Energy is rarely part of this assessment. When consumption rises after a change, the team cannot tell whether the increase is worth investigating, worth accepting, or neither. A change to tracing, retries or a shared component can affect consumption far beyond the modified component. This thesis asks how energy objectives can become actionable engineering instruments rather than reporting metrics. Site Reliability Engineering (SRE) answered a similar question for reliability with service-level indicators, objectives and response policies. We take SRE as the guiding research vision and study where the analogy holds for energy and where it breaks. An energy objective could, for example, bound the energy per successful transaction under stated workload conditions. The thesis connects three threads into one experimentally evaluated methodology. Useful-work semantics define what a successful transaction is. Energy attribution assigns shared and auxiliary consumption to transactions. Service-level engineering decisions act on the resulting energy objectives. Existing work covers attribution methods, measurement frameworks and sustainability objectives, mostly at component level and without a link to decisions. Our prior work on service-level energy modeling showed that the energy of auxiliary services is often overlooked and hard to measure. Planned experiments compare aggregate, request-normalized and useful-work-based indicators under controlled changes to observability configuration and injected failures. Whether transaction-level attribution is needed for these decisions, or whether service-level attribution with outcome counts is sufficient, is an open question the experiments are designed to answer.

### 7. Generating Property-Based Regression Tests from Source Code Semantics

- arXiv ID: `2611.32636v1`
- Authors: Clemens Bauer, Johann Glock, Martin Pinzger
- Published: 2026-11-24
- Categories: `cs.SE`
- Links: [abs](http://arxiv.org/abs/2611.32636v1) | [pdf](https://arxiv.org/pdf/2611.32636v1)

Conventional unit tests (CUTs) check a method under test at fixed concrete inputs. A test can therefore miss a regression if its input produces the expected output despite a fault. Property-based testing (PBT) checks universally quantified specifications across many randomly generated inputs, but writing properties and input generators by hand is difficult. Existing approaches automate PBT creation by generalizing an existing or generated unit test suite. They either over-approximate concrete inputs across repetitive tests or apply single-path symbolic analysis along concrete test runs. This paper presents an approach that derives property-based regression tests directly from source code semantics via multipath symbolic execution (SE). For each explored path through a target method, the approach records a path semantics comprising the path condition, the symbolic return value, and the state change map. Each path semantics induces a Hoare triple that compiles into an executable property. Because SE leaves parts of a class unspecified, the approach complements the generated properties with search-based CUTs for the whole class. We evaluate our Java implementation against EvoSuite and the test generalization tool Teralizer on EqBench and on 11 projects from TOGBench. On EqBench, our approach keeps validated properties for 82.0% of all methods. Its mean mutation score of 63.8% exceeds the 55.2% of EvoSuite and the 60.3% of Teralizer. On TOGBench, target selection, SE limitations, and property validation restrict validated properties to 2.8% of all methods. The resulting mean mutation score of 48.6% falls below the 50.9% of EvoSuite and the 51.1% of Teralizer. Failures during test generation leave a few classes without effective tests and lead to this gap.
