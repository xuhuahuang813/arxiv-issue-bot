### 1. SYCLDB: A Cross-Vendor Heterogeneous Analytical DBMS

- arXiv ID: `2611.30849v1`
- Authors: Ivan Donchev Kabadzhov, Eugenio Marinelli, Raja Appuswamy
- Published: 2026-11-23
- Categories: `cs.DB`, `cs.DC`
- Links: [abs](http://arxiv.org/abs/2611.30849v1) | [pdf](https://arxiv.org/pdf/2611.30849v1)

The rapid growth of AI and analytical workloads has increased the need for fast, interactive analytical data processing. This, in turn, has led to a surge of interest in designing accelerated analytical database engines that can exploit modern GPUs to scale computation. While GPUs provide the massive data-parallelism required by modern analytics, the software landscape remains dominated by closed-source, vendor-locked programming models, like CUDA, limiting portability across multi-vendor GPUs. In this work, we present SYCLDB, an end-to-end analytical database engine built upon the SYCL open standard, designed to enable efficient, hardware-agnostic execution across a wide range of accelerators using a single codebase. By implementing core relational operators as modular SYCL kernels, integrating them with a SQL frontend based on Apache Calcite and Apache Thrift, and supporting Apache Arrow for efficient columnar ingestion, SYCLDB reduces dependence on vendor-specific GPU programming stacks by enabling a single SYCL codebase to execute analytical query pipelines across Intel, AMD, and NVIDIA GPUs.

### 2. SignalCount: Approximate Counts with Structured and Semantic Predicates in Seconds

- arXiv ID: `2611.30779v1`
- Authors: Matteo Agius-D'Arrigo, Zachary Zelner, Harrison Ju, Rushab Munot
- Published: 2026-11-23
- Categories: `cs.DB`, `cs.AI`
- Links: [abs](http://arxiv.org/abs/2611.30779v1) | [pdf](https://arxiv.org/pdf/2611.30779v1)

Many applications store records with structured columns and a text document, and ask how many records in a filtered set meet a criterion that only a reader of the text can judge, such as "How many patients with type 2 diabetes, aged 40 to 70, stopped metformin because their blood sugar stayed high?" An interactive application needs this count in seconds, as the user types the criterion, to decide whether the matching set is worth materializing with a batch pipeline in which an LLM judges the records. Prior approximate query processing over such semantic predicates has an expensive model, the oracle, label a sample at query time, so every query waits for the oracle. We present SignalCount, a production system that answers COUNT queries with structured and semantic predicates and calls no oracle at query time, even for ad-hoc criteria. Its oracle is the production LLM judge, and the judge's logged verdicts calibrate, offline, the fast classifier that already runs in front of the judge. At query time, SignalCount counts the filtered set exactly and draws a uniform sample of at most 1,000 records in one columnar scan, scores the sample with the classifier, and multiplies the average calibrated probability by the exact count. Its 90% interval combines a sampling term with one-sided, rate-dependent margins for calibration error, fitted by split conformal prediction across tenants. In a multi-tenant production deployment, latency has a p99 of 3.8 s and stays flat as the filtered set grows beyond the sample. On tenants held out from fitting, the interval covers the count that the production pipeline returns in 92% of estimates, although estimates run about 15% high in aggregate, because a calibration nearly unbiased per record is still biased per criterion.

### 3. When an AI agent makes a mistake in a database, what decides the damage?

- arXiv ID: `2611.30483v1`
- Authors: Abdullah Kaya, Cevheri Bozoglan, Yusuf Gundogdu
- Published: 2026-11-23
- Categories: `cs.SE`, `cs.CR`, `cs.DB`
- Links: [abs](http://arxiv.org/abs/2611.30483v1) | [pdf](https://arxiv.org/pdf/2611.30483v1)

AI agents now run statements against production databases, and several of the incidents that followed deleted production data, which came back only through backups or the provider's help. We ask what decides the damage when such an agent makes a mistake: the model, a guard layer in front of the database, or the database engine itself. The study has two preregistered layers. In Layer A, a frozen library of 22 canonical mistakes is applied by script, with no model involved, to four relational engines under five permission arms and two recovery arms, followed by an engine-native recovery drill (792 cells; 874 drill runs including 10-minute repeats). In Layer B, a minimal tool-calling agent driven by six small open-weight models (4B to 12B parameters, plus one 35B mixture-of-experts model with about 3B active, served locally) works on tasks that contain hazards across nine engines: PostgreSQL, MySQL, SQLite, ClickHouse, Apache Cassandra, MongoDB, Valkey, Apache Kafka and OpenSearch (9,468 trials). A secondary run added MariaDB, Redis and Elasticsearch (2,916 trials); each behaved like its closest core engine. Out of the box, the engines differ less in what a mistake destroys than in what they let you undo. Three of the seven preregistered hypotheses met their decision rule: H2 (for one of nine damage classes) and H3 largely by construction of the arms, and H4 only under its original measure. Four did not; one of them (H5) was uninformative, because in its task the agents never found the credential. The post-hoc analyses (S1-S13) are exploratory and uncorrected for multiple comparisons; on PostgreSQL, MySQL, OpenSearch and ClickHouse the preregistered outcome and original-row loss disagree about G1. We report all of them, with every deviation from the preregistration and its timing.

### 4. Bound to be Complete: Efficient Verification for SQL Equivalence via U-Expressions

- arXiv ID: `2611.28516v1`
- Authors: Haoran Ding, Zhaoguo Wang, Zuming Jiang, Haibo Chen, Jinyang Li, Ruzica Piskac
- Published: 2026-11-21
- Categories: `cs.DB`, `cs.LO`
- Links: [abs](http://arxiv.org/abs/2611.28516v1) | [pdf](https://arxiv.org/pdf/2611.28516v1)

Automated verification of SQL query equivalence is a fundamental problem in database area. Recent works developed verifiers with guaranteed completeness, which can generate counterexamples to disprove non-equivalent queries and are useful in various scenarios. However, they have to solve complex formulas and can fail to produce counterexamples within a reasonable time budget.
  This paper presents a new complete verifier called SQLution, which not only greatly reduces the verification time, but also supports more SQL features. The key insight is to represent SQL semantics using U-expression, a functional algebra that can model SQL with significantly simpler formulas than prior works, thereby leading to more efficient SMT solving. To turn this insight into a practical verifier, SQLution further tackles two technical challenges associated with modeling SQL using U-expression, namely, the lack of tuple ordering and the presence of unbounded summations. In particular, to support tuple ordering, SQLution proposes order semantics encoding which combines U-expressions with first-order logic. To handle unbounded summation, SQLution introduces unbounded summation expansion to transform them into bounded summations, which can be directly encoded into FOL formulas. Evaluation shows that compared with state-of-the-art verifiers, SQLution can support all 271 non-equivalent query pairs derived from the Spider dataset and reduces verification time by up to 98.6%.

### 5. Shoonya: Zero-Socket In-Process Small Language Models for Graph Databases with Schema-Epoch KV Caching, Live Catalog Logit Masking, and Verifier-Advantage Distillation

- arXiv ID: `2611.28502v1`
- Authors: Madhulatha Mandarapu, Sandeep Kunkunuru
- Published: 2026-11-21
- Categories: `cs.DB`, `cs.LG`, `cs.PF`
- Links: [abs](http://arxiv.org/abs/2611.28502v1) | [pdf](https://arxiv.org/pdf/2611.28502v1)

Coupling a property-graph database to an external language-model server imposes a three-part socket tax: serialization overhead dwarfing microsecond graph reads, repeated prefill of verbose schemas, and blind decoding divorced from the live catalog and multi-version concurrency control (MVCC) engine. We present Shoonya, from-scratch commercially clean (0.0% non-commercial or share-alike data) tri-modal (Python, Rust, OpenCypher) small language models (16.8M to 1.07B parameters) co-designed with shoonya-infer, a zero-dependency pure-Rust runtime embedded inside the samyama-graph-enterprise address space. Direct GraphStore references unlock three database-native primitives: (1) an epoch-invalidated SchemaPrefixCache over a copy-on-write PagedKvArena accelerating warm CPU time-to-first-token by 4.91x--13.68x with O(1) DDL invalidation; (2) a 36 us columnar catalog and source-span logit mask enforcing valid ontology identifiers and verbatim spans; and (3) a sub-65 us read-only MVCC gate serving Tier-0 queries inside 389.8 MiB INT8 RSS (59.8--67.9 tok/s) with 0.0% hallucination leak. Rank-factorized tied embeddings (-74.5% vocabulary weights), atomic indentation tokens (0/421 indentation errors), 4:1 grouped-query attention with 2:1 cross-layer KV sharing (-93.75% INT8 KV memory), Warmup-Stable-Decay training, KnOTS SVD merging, Step-GRPO, and Rust Jacobi SVD governance keep 100% of layers heavy-tailed ($α\in [1.88, 2.20]$). Finally, we synthesize nine lessons across v0.1--v1.0, resolving a Reverse-Token-Density Distillation Trap via teacher scaling and zero-VRAM Verifier-Advantage-Gated Knowledge Distillation (AdvKD), recovering +13.61 MBPP points (33.07%) while reaching 100% validity on enrichment, grounded extraction, and tool planning.

### 6. Interrupt-Aware Static Detection of Deadlocks in Rust Operating Systems

- arXiv ID: `2611.30713v1`
- Authors: Yuzhi Li, Hongliang Tian, Chengjun Chen, Jianfeng Jiang, Hui Xu
- Published: 2026-11-23
- Categories: `cs.SE`
- Links: [abs](http://arxiv.org/abs/2611.30713v1) | [pdf](https://arxiv.org/pdf/2611.30713v1)

Rust is increasingly adopted in operating systems, but Rust's safety guarantees do not eliminate deadlocks, especially those induced by interrupts. The core challenge is to recover interrupt-sensitive lock dependencies from Rust's guard-based synchronization across function boundaries. Applying this analysis across Rust OS projects also requires specifying project-specific synchronization semantics. We present an approach combining interrupt-aware static analysis with diagnostic-guided agent auditing for detecting deadlocks in Rust operating systems. Our approach uses lightweight source-level annotations to recover project-specific lock and interrupt semantics, performs a flow-sensitive MIR-based analysis to track lock-holding and interrupt states, and reports potential deadlocks with supporting evidence. An agent then searches for relevant source code in the repository and returns a confidence assessment with reasons for each supplied report. We evaluate our tool on four real Rust operating systems, identifying 26 true cases corresponding to nine maintainer-confirmed defects. Diagnostic-guided auditing achieves 86.2\% precision and 96.2\% recall based on static analysis results, and offers advantages over the baselines in both cost and effectiveness.

### 7. ReproShift: Cross-Version Adaptation of Linux Kernel Fuzzing Crash Reproducers

- arXiv ID: `2611.30655v1`
- Authors: Changjian Liu, Zhiwen Tang, Xianying Wang, Fan Ding, Zhengshu Wang, Chao Hu, Yuheng Shen, Ying Fu, Heyuan Shi
- Published: 2026-11-23
- Categories: `cs.SE`
- Links: [abs](http://arxiv.org/abs/2611.30655v1) | [pdf](https://arxiv.org/pdf/2611.30655v1)

Reliable crash reproduction is essential for diagnosing and repairing kernel crashes. Historical crash reproducers preserve concrete bug-triggering knowledge and can be reused for regression testing, bug revalidation, and impact analysis across kernel versions. However, kernel evolution can invalidate these reproducers by changing kernel interfaces, configurations, and execution paths. Migrating them is therefore challenging: the adapted reproducer must identify and modify version-sensitive behavior while preserving the bug-triggering operations and resource dependencies that define the original crash. To address this challenge, we propose ReproShift, an automated framework for cross-version crash reproducer migration by preserving bug-triggering semantics while adapting only version-sensitive behavior. Given source crash artifacts, a source crash reproducer, and a target kernel, ReproShift produces a migrated crash reproducer with same-bug validation evidence. Specifically, ReproShift first constructs a structured source-to-target context to identify migration-relevant kernel changes. It then performs constrained target-aware adaptation to revise version-sensitive reproducer operations while preserving the original trigger logic. Finally, it executes the adapted candidates on the target kernel and uses execution feedback and case-specific crash evidence to iteratively validate candidates and refine subsequent migrations. In a real-world deployment on an evolving upstream kernel, ReproShift further produces 22 upstream crash reports generated from adapted candidates, of which 7 have been fixed and 5 have received explicit maintainer confirmation. To systematically quantify its migration effectiveness, we construct a benchmark of 107 real-world source-target migration cases. ReproShift achieves confirmed same-bug migration in 57 cases, compared with 19 cases using direct replay.

### 8. POMA: Beyond Final Flags -- Process-Level Evaluation of Base LLMs in Vulnerability Exploitation

- arXiv ID: `2611.30590v1`
- Authors: Gufeng Zhang, Yiru Zhao, Shengyu Liu, Weichen Yan, Xingwang Xiang, Yiran Ma, Benxiao Tang, Lei Zhao, Jinxin Ma
- Published: 2026-11-23
- Categories: `cs.CR`, `cs.SE`
- Links: [abs](http://arxiv.org/abs/2611.30590v1) | [pdf](https://arxiv.org/pdf/2611.30590v1)

As large language models (LLMs) evolve from text generation to autonomous software-engineering execution, automated vulnerability exploitability verification has emerged as a vital frontier in software quality assurance and security validation. Existing security benchmarks, however, largely judge models by binary pass/fail outcomes or coarse stage milestones. Such outcome-centric scoring obscures fine-grained failure dynamics across long-horizon execution and conflates the intrinsic capability of a base LLM with external agent scaffolding. We present POMA (Pwn-Oriented Model Assessment), a process-level evaluation methodology and platform that isolates base LLMs under a unified execution baseline -- fixing task inputs, tool interfaces, target environments, feedback formats, and execution budgets -- while measuring intermediate states and transitions from runtime evidence. Evaluating four frontier base LLMs across 55 CTF Pwn challenges and 10 real-world vulnerability reproduction tasks exposes persistent capability attrition along the exploitation chain: from vulnerability knowledge to executable implementation, from client-side actions to verified target states, from failure localization to precise repair, and across iterative revisions. In real-world software, models further struggle to satisfy format, semantic, differential, and crash-identity constraints simultaneously. By pinpointing where execution chains break down, POMA provides an empirical foundation for trustworthy capability assessment and principled vulnerability-agent design. Our benchmark catalogs, process-measurement evaluator, and sample harness are publicly available at https://github.com/maple-pwn/poma-release .

### 9. LeanReviewBench: Semantic Alignment Review in Mathematical Lean Projects

- arXiv ID: `2611.30361v1`
- Authors: Ruichen Qiu, Hao Shen, Lihong Zhi, Xiao-Shan Gao
- Published: 2026-11-23
- Categories: `cs.CL`, `cs.SE`
- Links: [abs](http://arxiv.org/abs/2611.30361v1) | [pdf](https://arxiv.org/pdf/2611.30361v1)

Lean verifies that a proof establishes its formal proposition, but whether that proposition preserves the mathematical content of an informal source requires separate review. In project-scale formalizations, this correspondence can depend on definitions and constraints distributed across many declarations. We introduce LeanReviewBench, a benchmark for project-level semantic alignment review containing 197 versioned inputs collected from 18 real Lean projects, with 87 aligned and 110 misaligned reference judgments. Each input binds an informal mathematical target to selected formal declarations and an extracted dependency context. Construction combines development-history discovery, independent target binding, reconstruction under a common Lean environment, and Astra annotation with human review of uncertain cases. The collection spans diverse mathematical domains and includes 69 historical pairs. We evaluate six language models with Direct and ReForm prompts on all 197 inputs against final human-reviewed reference labels. GPT-6.1 Sol with Direct prompting achieves the highest reported accuracy of 0.827 and misalignment-detection F1 of 0.844; the effects of prompting vary across models. LeanReviewBench provides a testbed for reviewing semantic correspondence in existing mathematical formalization projects. LeanReviewBench is available at https://github.com/MechMath/LeanReviewBench.

### 10. AEGIS: Evidence-Guided Set Decisions for Requirement-to-Code Traceability

- arXiv ID: `2611.30093v1`
- Authors: Zhiyao Wang, Yiming Peng, Munan Li, Mingyue Zhang, Guanghong Li, Jialong Li, Tatsuhiro Tsuchiya
- Published: 2026-11-23
- Categories: `cs.SE`
- Links: [abs](http://arxiv.org/abs/2611.30093v1) | [pdf](https://arxiv.org/pdf/2611.30093v1)

Requirement-to-code traceability recovery identifies code artifacts that implement a requirement, but manual review costs limit how many candidates developers can inspect. Code relations can reveal candidates missed by textual retrieval, yet can also introduce code unrelated to the requirement. We propose AEGIS, which combines retrieval evidence and code relations to construct and revise trace sets under a project-wide review budget. Grouped retrieval and semantic retrieval supply candidates. A set objective combines relevance to the requirement with structural compatibility. Local search constructs sets of different sizes, and dynamic programming selects one set per requirement within the budget. Call-context admission then compares replacements using evidence from arguments and return values in calls involving protected members, while bounding retrieval-score loss. Across 13 projects, AEGIS achieves the highest project-macro average on nine of ten evaluation metrics among the compared methods. Relative to same-corpus adaptations of TAROT-VSM and FTLR+MC, it improves F$_1$@5 by 33.21% and 52.28%, and MAP by 38.58% and 49.08%, respectively.

### 11. Can Vibe Coding Produce Accessible Websites: An Empirical Study on LLM Coding Agents and Skills

- arXiv ID: `2611.29822v1`
- Authors: Syed Fatiul Huq, Md. Asif Haider, Abu Jafar Saifullah, Thomas Zimmermann, Sam Malek
- Published: 2026-11-22
- Categories: `cs.SE`, `cs.AI`
- Links: [abs](http://arxiv.org/abs/2611.29822v1) | [pdf](https://arxiv.org/pdf/2611.29822v1)

Large language model (LLM) coding agents increasingly allow developers and non-professionals to create websites through natural-language instructions, with limited inspection of the generated source code. Although this ``vibe coding'' workflow lowers barriers to software creation, it may also propagate accessibility defects at scale. We investigate the accessibility of websites generated end-to-end by contemporary coding agents and whether agent-level accessibility interventions improve their output. We generated 90 websites for three projects using combinations of three coding agents, four language models, and multiple reasoning-effort levels. We evaluated complete interaction journeys using axe-core, IBM Equal Access Accessibility Checker, and QualWeb, and converged reports to observe violation prevalence and violated WCAG Success Criterion (SC). None of the 90 baseline websites was fully accessible, with an average of 80.43 violated interface elements. 13 WCAG SCs were violated at least once across the runs. Color contrast was the most prevalent issue, followed by labeling, semantic-structure, keyboard, and visualization failures. We reran 24 matched configurations with a general accessibility Skill and a contrast-specific Skill. Both significantly improved accessibility scores, but neither eliminated violations. User testing with blind individuals corroborated the experiential effects of the detected inaccessibilities. Moreover, functional correctness decreased with the inclusion of Skills. Our findings show that accessibility does not reliably emerge from vibe coding, and agentic interventions can both improve some accessibility issues and introduce new functional ones.

### 12. ReqSeek: Transformer-Based Automatic Requirements Identification for Building Large Requirements Datasets

- arXiv ID: `2611.29722v1`
- Authors: Mohammad Kasra Habib,  Umm-e-Habiba, Daniel Graziotin, Stefan Wagner
- Published: 2026-11-22
- Categories: `cs.SE`, `cs.CL`
- Links: [abs](http://arxiv.org/abs/2611.29722v1) | [pdf](https://arxiv.org/pdf/2611.29722v1)

Large, diverse, and high-quality datasets are significant for advancing AI in requirements engineering, yet automated identification of requirements from Software Requirement Specifications (SRS) remains a challenge. Automatic Requirements Identification (ARI) methods demonstrate limited generalization to unseen documents across heterogeneous SRSs. This work presents ReqSeek, a transformer-based, domain-agnostic ARI model for recognizing ISO 29148-style requirements in SRS documents, supporting dataset construction. We curated the Automatic Requirements Identification Dataset (ARID), comprising 2,396 training instances from 23 heterogeneous SRSs, and fine-tuned four transformer architectures. RoBERTa was selected as the base model for ReqSeek and achieved 95% precision, recall, F1, and F0.89 on the held-out evaluation set. Exploratory human-model benchmarking showed performance comparable to humans while requiring substantially less prediction time than manual annotation. Post-hoc evaluation on out-of-domain (OoD) SRSs provided evidence of requirement identification beyond ARID. Robustness analysis demonstrated ReqSeek's insensitivity to minor linguistic variations while maintaining sensitivity to major ISO 29148-style violations. We applied ReqSeek to construct the Software Requirements Dataset (SwaRD), identifying 10,201 ISO 29148-style requirements from 231 industrial SRSs. SwaRD aligns with textual and semantic properties of human-curated datasets while exceeding them in scale and domain diversity. Our results suggest that transformer-based ARI can provide precise and generalizable requirements identification.
